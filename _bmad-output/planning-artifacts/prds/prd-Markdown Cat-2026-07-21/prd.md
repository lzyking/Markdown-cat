# PRD: 便携绿色 Markdown 编辑器

## 0. 文档目的

本文档为 Markdown Cat 的 MVP 产品需求文档，目标读者为产品经理、架构师、UX 设计师和开发团队。文档以术语表（Glossary）统一词汇，以功能分组 + 全局编号的功能需求（FR）描述可交付能力，并在需要用户确认或尚未明确处用 `[ASSUMPTION]` 标签标注。PRD 基于已批准的 [Brief](/_bmad-output/planning-artifacts/briefs/brief-Markdown%20Cat-2026-07-21/brief.md) 和 [Architecture Spine](/_bmad-output/planning-artifacts/architecture/architecture-Markdown%20Cat-2026-07-21/ARCHITECTURE-SPINE.md) 编写，不重复其中的技术实现细节，只陈述产品层必须做什么与为什么。

## 1. 愿景

在企业受控的 Mac 电脑上，员工常常没有管理员权限，无法安装 Typora、VS Code 这类需要安装的编辑器。他们想快速记下一条工作日志、一段技术思考或一份周报素材时，往往被迫选择不支持 Markdown 的笔记工具，或把内容锁在专有格式里。Markdown Cat 是一款**无需安装、双击即可运行**的绿色桌面应用，放在任意文件夹或 U 盘里都能工作。它提供左栏源码、右栏实时预览的双栏编辑体验，内容以原生 `.md` 文件保存在应用所在目录，按键即自动保存，不锁格式、不丢数据，让知识工作者三秒内开始记录，关闭时无需担心保存。

MVP 要验证的核心假设是：在权限受限的 macOS 环境下，用户愿意为「零安装 + 原生 Markdown 文件 + 双栏实时预览」这款组合持续使用一款轻量编辑器。

## 2. 目标用户

### 2.1 Jobs To Be Done

- **JTBD-1**：当我突然收到任务或灵光一闪时，我能在三秒内打开编辑器并写下 Markdown，而不需要等待安装或权限审批。
- **JTBD-2**：当我写完工作日志或技术笔记后，我能以普通 `.md` 文件保存，方便后续在 Obsidian、Git、VS Code 或 Confluence 里继续使用。
- **JTBD-3**：当我身处一台受控 Mac 时，我无需管理员权限就能运行编辑器，也不用担心应用向系统目录写入痕迹。
- **JTBD-4**：当我输入 Markdown 时，我能立即看到渲染效果，确保表格、列表、代码块等格式正确。

### 2.2 非用户（v1 不服务）

- 需要多用户实时协作的团队成员。
- 需要 Confluence / 云端同步直接集成的用户。
- 需要主题、插件、版本历史等高级功能的高级 Markdown 用户。
- 主要使用 Windows 的用户（MVP 仅支持 macOS，Windows 列为 v2 目标）。

### 2.3 关键用户旅程

- **UJ-1. 小林在受控 Mac 上打开应用并记录一条工作日志。**
  - **主角与场景**：小林，后端工程师，在公司配发的 MacBook Pro 上无管理员权限。周会刚结束，他想记录一条待办。
  - **入口状态**：应用已放在 `~/Documents/tools/` 中，从未运行过；他双击应用图标。
  - **路径**：
    1. 应用在 3 秒内打开，呈现双栏编辑界面。
    2. 左栏显示空白文档，标题栏显示默认文件名 `New_20260721_143052.md`。
    3. 小林输入 Markdown 工作日志，右栏实时渲染。
    4. 他停止输入约 300ms 后，状态栏显示「已保存」或保存失败的明确提示。
    5. 他关闭应用，重新打开后内容仍在。
  - **高潮**：小林无需点击 Save，内容已以 `.md` 文件保存在应用目录，可直接复制到 Git 或周报工具。
  - **结局**：小林下次需要记录时，再次双击即可使用，无需配置。
  - **边缘情况**：如果应用所在目录不可写，保存失败后 UI 必须明确提示，且不清空编辑器内容；小林可改到可写路径继续。

- **UJ-2. 小林在菜单中修改 Markdown 保存路径。**
  - **入口状态**：应用已运行，左栏有内容，当前文件已保存。
  - **路径**：
    1. 他点击菜单「Markdown Cat > 设置保存路径…」。
    2. 系统文件夹选择器弹出，他选择新的目录（如 `~/Notes`）。
    3. 路径写入本地配置文件，后续新建文档默认保存到新路径。
    4. 当前已打开文档的位置不变，除非他手动另存。
  - **高潮**：保存路径持久化，重启应用后仍然有效。
  - **结局**：小林后续所有新建文档都按新路径保存。

## 3. 术语表

- **应用目录（App Directory）** — 应用可执行文件所在目录。MVP 默认将 `.md` 文件保存于此。[ASSUMPTION: 用户接受默认保存位置与应用目录一致，可通过设置更改。]
- **当前文档（Current Document）** — 用户当前正在编辑的 Markdown 文件，包含源码字符串和文件路径两个状态。
- **源码编辑器（Source Editor）** — 左栏用于编辑 Markdown 源码的输入区。
- **预览区（Preview Pane）** — 右栏用于渲染 Markdown 的只读区域。
- **应用可写目录（App Writable Directory）** — 应用运行时可写入配置文件的目录。MVP 默认优先使用应用目录；当应用目录不可写时，回退到 `~/Documents/MarkdownCat`（若不存在则自动创建）。该目录不得位于系统目录或需要管理员权限的位置。
- **防抖保存（Debounced Save）** — 用户停止输入后等待 300ms 自动触发的文件保存机制。
- **保存路径（Save Path）** — 用户配置的 `.md` 文件默认保存目录，通过系统文件选择器设置并写入本地配置。
- **绿色应用（Portable App）** — 无需安装、不写系统注册表、不依赖管理员权限即可运行的应用。
- **配置文件（Config File）** — 应用可写目录中的本地 JSON 文件，保存用户设置（如保存路径）。
- **原生 Markdown 文件（Native Markdown File）** — 标准 `.md` 文件，使用 UTF-8 编码，可被其他工具直接打开。

## 4. 功能

### 4.1 启动与默认文档

**描述：** 应用启动后，立即为用户准备一个新的空白 Markdown 文档。默认文件名以 `New_YYYYMMDD_HHMMSS_mmm.md` 格式生成，时间戳取自启动时刻。用户无需手动新建或命名即可开始输入。实时化 UJ-1。

**Functional Requirements:**

#### FR-1: 启动时创建新文档

应用在启动后 1 秒内呈现一个空白文档，文件名按 `New_YYYYMMDD_HHMMSS_mmm.md`（毫秒时间戳）生成。实现 UJ-1。

**Consequences：**
- 启动到可输入时间不超过 3 秒（从双击到光标在源码编辑器中可用）。
- 文件名包含启动时的本地日期和时间，格式固定为 `New_YYYYMMDD_HHMMSS_mmm.md`，其中 `mmm` 为毫秒（000–999），确保同一秒内多次启动不会覆盖已有文件。
- 若同一毫秒已存在同名文件，则等待下一毫秒后重新生成文件名，确保文件唯一性。
- 文档内容初始为空字符串，标题栏或状态栏显示当前文件名。

**Out of Scope：**
- 启动时恢复上次关闭前的文档；[NON-GOAL for MVP] 在启动时恢复会话状态。
- 启动时显示最近文件列表；[NON-GOAL for MVP] 文件管理功能。

#### FR-2: 默认保存位置

新文档默认保存到 **应用目录** 下；当应用目录不可写时，回退到 `~/Documents/MarkdownCat`（不存在则自动创建）。用户可通过设置更改保存路径。实现 UJ-1。

**Consequences：**
- 保存操作发生在后端，返回成功或失败状态。
- 保存路径不可写时，保存失败并在 UI 中提示，编辑器内容保留；同时引导用户到设置中更改保存路径。
- 文件名中的毫秒时间戳确保同一秒内多次启动也不会覆盖已有文件。

**Out of Scope：**
- 自动创建子目录分类；[NON-GOAL for MVP] 文档组织。

### 4.2 双栏编辑与实时预览

**描述：** 主界面为左栏源码、右栏预览的双栏布局。用户在源码编辑器中输入 Markdown，预览区实时渲染。两栏共享同一份字符串状态，禁止预览区直接修改内容。实时化 UJ-1。

**Functional Requirements:**

#### FR-3: 源码编辑

用户可在左栏源码编辑器中输入和编辑 Markdown 源码。实现 UJ-1。

**Consequences：**
- 支持常见 Markdown 语法输入：标题、段落、列表、代码块、行内代码、加粗、斜体、链接、引用、分隔线。
- 编辑器支持基础文本操作：撤销、重做、复制、粘贴、全选、光标移动。
- 编辑器区域不可隐藏或关闭，以保证双栏模型始终成立。

**Out of Scope：**
- Markdown 语法自动补全或快捷按钮；[NON-GOAL for MVP] 工具栏格式按钮。
- 图片、附件的插入与渲染；[NON-GOAL for MVP] 富媒体。
- 多标签页或多文档同时编辑；[NON-GOAL for MVP] 多文档管理。

#### FR-4: 实时预览

用户在源码编辑器中输入时，右栏预览区在 100ms 内同步更新渲染结果。实现 UJ-1。

**Consequences：**
- 预览区为只读，用户无法直接修改渲染内容。
- 预览渲染结果与源码一致，常见语法渲染无明显异常。
- 预览区滚动位置与编辑器位置保持松耦合，不因输入跳动。

**Out of Scope：**
- 源码与预览的同步滚动；[NON-GOAL for MVP] 精确同步滚动。
- 导出为 HTML 或 PDF；[NON-GOAL for MVP] 导出功能。
- 自定义 CSS 主题；[NON-GOAL for MVP] 主题系统。

### 4.3 按键级自动保存

**描述：** 编辑器状态变化后触发防抖保存。默认防抖时间为 300ms，保存失败时在 UI 中提示用户，并保留当前编辑状态。前端根据保存状态更新状态栏指示。实时化 UJ-1。

**Functional Requirements:**

#### FR-5: 防抖自动保存

用户停止输入 300ms 后，系统自动将当前文档写入文件。实现 UJ-1。

**Consequences：**
- 每次按键触发状态更新，但保存只在防抖间隔后执行一次。
- 保存成功后状态栏显示「已保存至 {filename}」提示。
- 保存失败时状态栏显示「保存失败：{reason}」，并保持可见，直到用户下一次成功保存或关闭当前提示。
- 保存失败期间用户可继续编辑，内容不丢失。

**Out of Scope：**
- 手动保存快捷键或按钮；[NON-GOAL for MVP] 显式手动保存入口。
- 保存历史或版本回退；[NON-GOAL for MVP] 版本历史。

#### FR-6: 保存失败处理

当保存失败时，系统必须明确提示用户并保留编辑状态。实现 UJ-1。

**Consequences：**
- 保存失败的原因包括但不限于：目标目录不可写、磁盘已满、文件被占用。
- UI 提示至少包含「保存失败」文本和失败原因（如路径不可写）。
- 编辑器内容保持原状，不自动清空或回滚。

### 4.4 保存路径设置

**描述：** 用户可通过菜单设置 `.md` 文件的默认保存路径。设置使用系统文件夹选择器，路径持久化到本地配置文件，重启后仍有效。实时化 UJ-2。

**Functional Requirements:**

#### FR-7: 设置保存路径

用户可在菜单中打开系统文件夹选择器，选择一个目录作为新的默认保存路径。实现 UJ-2。

**Consequences：**
- 设置项位于菜单「Markdown Cat > 设置保存路径…」。
- 选择器仅允许选择已存在的文件夹。
- 用户确认后，新路径写入配置文件，立即生效。
- 后续新建文档默认使用新路径。
- 当前已打开文档的文件路径不自动改变。

**Out of Scope：**
- 创建新文件夹；[NON-GOAL for MVP] 用户需在选择器外创建文件夹。
- 多个保存路径或快速切换；[NON-GOAL for MVP] 多路径管理。

#### FR-8: 配置持久化

保存路径在应用重启后保持不变。实现 UJ-2。

**Consequences：**
- 配置文件以 JSON 格式存储于应用可写目录（定义见术语表）。
- 配置文件损坏或缺失时，应用回退到默认保存路径规则（应用目录可写则用之，否则回退到 `~/Documents/MarkdownCat`）。
- 配置读取失败时 UI 不阻断，用户可继续编辑。

**Out of Scope：**
- 云端同步配置；[NON-GOAL for MVP] 任何云服务。
- 多配置文件或导入/导出设置；[NON-GOAL for MVP] 设置导入导出。

## 5. 非目标（明确不做）

- **图片粘贴与附件管理**：MVP 不处理图片粘贴、截图插入或 `assets/` 目录。图片粘贴已列为紧随 MVP 的 Should 项（优先级：P1），但不在本次交付范围。
- **多标签 / 多文档**：MVP 只处理单个当前文档，没有文件树、最近打开列表或文档管理。打开已有 `.md` 文件同样列为紧随 MVP 的 Should 项（优先级：P2），MVP 仅支持新建文档。
- **导出 HTML / PDF / 打印**：MVP 只输出原生 `.md` 文件，用户可借助其他工具转换。
- **主题、插件、自定义样式**：MVP 使用一套默认渲染样式，不支持用户自定义。
- **Confluence 同步 / 云服务 / 多用户协作**：MVP 完全离线，无网络依赖，无账户体系。
- **Windows 版本**：MVP 仅支持 macOS，Windows 10/11 为 v2 目标。
- **启动恢复会话**：应用启动时始终新建空白文档，不恢复上次关闭时的内容或窗口状态。
- **手动保存按钮 / 快捷键**：MVP 完全依赖自动保存，不提供显式手动保存入口。

## 6. MVP 范围

### 6.1 在范围内

- 启动后创建空白文档，默认文件名 `New_YYYYMMDD_HHMMSS_mmm.md`。
- 左栏源码编辑 + 右栏实时预览。
- 常见 Markdown 语法渲染：标题、段落、列表、代码块、行内代码、加粗、斜体、链接、引用、分隔线。
- 按键级防抖自动保存（300ms），保存失败提示用户并保留内容。
- 菜单中设置默认保存路径，路径持久化到本地 JSON 配置。

### 6.2 在范围外（MVP 不做）

- 图片粘贴与 `assets/` 目录管理（列为 Should P1，但本次不实现）。
- 打开已有 `.md` 文件（列为 Should P2，MVP 仅新建文档）。
- 多文档、文件树、最近打开列表。
- 导出、打印、主题、插件。
- 云同步、协作、Confluence 集成。
- Windows 版本。
- 启动时恢复上次会话。
- 手动保存入口。

## 7. 成功指标

**Primary**

- **SM-1**：从双击应用到光标可用的时间 < 3 秒。
  - **Measurement Method**：在 macOS 14 的受控测试机（无管理员权限账户）上，使用自动化脚本或秒表，从双击 `.app` 到源码编辑器获得 focus 可输入，连续测量 5 次取平均值。
  - **Target**：平均值 < 3 秒；5 次中无一次 ≥ 4 秒。
  - **Owner**：QA / 开发负责人。
  - **Pass Criteria**：平均值达标且无明显卡顿。
  - **验证 FR**：FR-1。
- **SM-2**：用户连续输入 100 字，期间未发生数据丢失。
  - **Measurement Method**：在受控测试机上，以每分钟 200 字速度输入一段 100 字 Markdown 文本，输入过程中模拟网络/磁盘无异常，输入结束后等待 5 秒，关闭应用并重新打开，检查文件内容与原输入一致。
  - **Target**：100% 一致；无字符丢失、乱码、顺序错乱或文件损坏。
  - **Owner**：QA。
  - **Pass Criteria**：文件 SHA-256 与预期文本一致，且能在 VS Code 中正常打开。
  - **验证 FR**：FR-5、FR-6。
- **SM-3**：生成的 `.md` 文件在 VS Code、Obsidian、Git 中直接打开且渲染无异常。
  - **Measurement Method**：使用 MVP 生成 5 份包含不同 Markdown 元素（标题、列表、代码块、行内代码、链接、引用、分隔线）的 `.md` 文件，分别在 VS Code、Obsidian 预览、Git 仓库中查看。
  - **Target**：所有文件在三种工具中均可打开，渲染结果与 MVP 预览区一致，无格式断裂或乱码。
  - **Owner**：产品经理 + QA。
  - **Pass Criteria**：三种工具均通过目视检查，无 P0 渲染异常。
  - **验证 FR**：FR-2、FR-4。

**Secondary**

- **SM-4**：在受控 Mac 上无需管理员权限即可运行。
  - **Measurement Method**：在从未安装过 Markdown Cat 的受控 Mac 上，将应用包复制到 `~/Documents/tools/`，直接双击运行；测试期间不输入管理员密码。
  - **Target**：应用可正常启动、编辑、保存、退出，无需 sudo 或系统偏好设置授权。
  - **Owner**：QA / 产品经理。
  - **Pass Criteria**：全程无管理员权限提示，保存/配置写入成功。
  - **验证**：绿色应用原则（§5 非目标与 §8 约束）。
- **SM-5**：设置保存路径后，重启应用路径仍然有效。
  - **Measurement Method**：通过菜单设置保存路径为 `~/Notes/MarkdownCat`，保存后关闭应用，重新打开，新建文档并检查默认保存位置。
  - **Target**：重启后首次新建文档保存到 `~/Notes/MarkdownCat`。
  - **Owner**：QA。
  - **Pass Criteria**：配置文件读取成功，新建文档路径与设置一致。
  - **验证 FR**：FR-8。

**Counter-metrics（不要优化）**

- **SM-C1**：启动速度不应以牺牲错误提示质量为代价。不要为了压缩启动时间而隐藏保存失败或配置读取失败的信息。
- **SM-C2**：自动保存频率不应以磁盘寿命为优先。300ms 防抖是为了平衡响应与写盘次数，不要进一步缩短防抖时间导致无意义写盘。

## 8. 跨领域非功能性需求

- **NFR-1（性能）**：启动到可输入 < 3 秒；预览更新延迟 < 100ms；防抖保存间隔 300ms。
- **NFR-2（可靠性）**：保存失败必须保留编辑状态并提示，禁止静默丢失数据。
- **NFR-3（可移植性）**：应用包为单 `.app`，无需安装；运行时配置与业务数据写入应用可写目录（定义见术语表），不修改系统注册表或 `/Applications` 等系统目录；Tauri 框架日志可写入 `~/Library/Application Support/com.markdowncat.dev`，但应用自身文档与配置仍仅写入应用可写目录或用户选择的保存目录，禁止向用户 Library 的偏好目录等其他系统位置写入。
- **NFR-4（兼容性）**：生成的 `.md` 文件使用 UTF-8 编码，文件名使用 ASCII 安全字符（`New_` 前缀默认且不可配置），路径使用相对路径或用户配置的标准绝对路径，确保在其他编辑器中可读。
- **NFR-5（可访问性）**：状态栏提示文字清晰可读，错误状态使用对比色或图标区分，但不强制达到 WCAG 2.1 AA。

## 10. 假设索引

- **ASSUMPTION-1**：默认保存路径优先为应用目录；不可写时回退到 `~/Documents/MarkdownCat`（不存在则自动创建）。来源：§4.1、Brief §7。
- **ASSUMPTION-2**：用户接受 MVP 没有图片粘贴功能，图片粘贴列为紧随 MVP 的 Should P1。来源：§4.2、Brief §7。
- **ASSUMPTION-3**：MVP 不处理用户手动打开已有 `.md` 文件的场景，仅支持启动时新建文档；打开已有文件列为 Should P2。来源：§9 OQ-3、用户确认。
- **ASSUMPTION-4**：用户无需启动时恢复上次会话，每次启动新建空白文档。来源：Brief §7、§5 非目标。
- **ASSUMPTION-5**：预览延迟 100ms 为上限，实际实现以 60fps 下的流畅体验为准。来源：§7 成功指标、NFR-1。
- **ASSUMPTION-6**：状态栏提示使用中文，MVP 不做多语言支持，但字符串统一放入 locale 文件避免硬编码。来源：§9 OQ-5。

## 11. 发布标准（Release Criteria）

MVP 上线前必须满足以下条件：

1. 所有在 §6.1 范围内的功能已实现并通过 QA 测试。
2. 成功指标 SM-1、SM-2、SM-3 全部通过；SM-4、SM-5 至少达到可接受标准。
3. 在受控 Mac（无管理员权限账户）上完成 Gatekeeper 右键「打开」测试，结果与 OQ-2 的 Fallback Decision 一致。
4. 开放问题 OQ-1 至 OQ-5 已关闭，或已按 Fallback Decision 记录并同步至团队。
5. 生成的 `.md` 文件在 VS Code、Obsidian、Git 中验证无 P0 渲染异常。
6. 应用包可在未安装的 macOS 上直接运行，无需 sudo 或管理员授权，配置写入成功。
7. 无未解决的 P0 缺陷阻塞自动保存、启动或配置读取。
