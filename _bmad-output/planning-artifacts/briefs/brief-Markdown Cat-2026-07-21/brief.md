# 便携绿色 Markdown 编辑器

## 1. 一句话概述

一款**无需安装、双击即可运行**的 macOS 桌面 Markdown 编辑器，让没有管理员权限的用户也能随时打开、快速记录，并以原生 Markdown 格式保存，便于后续迁移到其他工具（如 Confluence、Git、Obsidian）。

## 2. 问题

在公司受控的 Mac 电脑上，用户往往没有管理员权限，无法安装普通软件。现有工具要么需要安装（Typora、VS Code）、要么不支持 Markdown（OneNote）、要么体验不够轻量（在线编辑器）。结果是：

- 想快速记一条工作日志或技术笔记时，**启动成本过高**；
- 写好的内容**锁在专有格式里**，复制到其他系统时格式或图片路径会断裂；
- 用户需要**手动管理文件路径和图片**，迁移过程容易出错。

## 3. 解决方案

一个绿色便携的桌面应用，放在任意文件夹或 U 盘里都能运行。打开即用，左栏写 Markdown 源码，右栏实时预览，内容以普通 `.md` 文件保存在**应用所在目录**下，按键即自动保存，无需手动点击 Save。用户也可在菜单中更改保存路径。

## 4. 目标用户

**主要用户**：在企业 Mac 上工作、无管理员权限、需要频繁记录技术笔记/工作日志的知识工作者。

**成功场景**：用户收到一个任务或灵光一闪，三秒内打开编辑器、写下 Markdown，关闭时无需担心内容丢失；当周报复盘或写文档时，直接复制 `.md` 文件到其他系统即可。

## 5. 差异化要点

- **零安装**：无需管理员权限，不写入系统目录，适合受控环境；
- **文件原生可见**：每个笔记都是普通 `.md` 文件，不锁在私有数据库里；
- **双栏实时预览**：保留 Markdown 源码的控制力，同时即时看到渲染效果；
- **为迁移而设计**：后续图片采用与文件同目录的 `assets/` 相对路径，避免迁移时路径断裂。

## 6. 成功标准

- 从启动到可输入的时间 < 3 秒；
- 用户输入过程中无数据丢失（按键级自动保存）；
- 生成的 `.md` 文件可以在 VS Code、Obsidian、Git 中直接打开且无渲染异常；
- 在受控 Mac 上可正常运行，无需安装或管理员权限。

## 7. 范围（MVP）

### 包含（Must）

1. 启动时打开空白新文档，默认文件名 `New_YYYYMMDD_HHMMSS.md`；
2. 双栏界面：左栏源码编辑，右栏实时预览；
3. 支持常见 Markdown 语法的实时渲染；
4. 按键即自动保存，保存失败时提示用户；
5. 菜单中可设置 `.md` 文件的存储路径，路径写入配置文件。

### 包含（Should，紧随 MVP）

- 粘贴图片，图片保存为与当前 `.md` 同目录的 `assets/` 相对路径。

### 不包含（Won't This Time）

- Confluence 同步；
- 多用户协作；
- 插件/主题扩展；
- 版本历史。

### 平台

- **MVP**：macOS（macBook Pro）。
- **第二版**：Windows 10 / Windows 11。

## 8. 技术方案（初步）

采用 **Tauri（Rust + Web 前端）** 构建，原因：

- 打包为单文件绿色应用，无需安装；
- 跨平台能力强，MVP 在 macOS 验证后，Windows 版本可复用大部分代码；
- 包体积小、启动快，符合“随时打开”的使用场景；
- 文件系统访问能力强，便于实现自动保存和本地 `.md` 文件管理。

前端编辑器组件（如 CodeMirror、Monaco）和 Markdown 渲染库的选择，在后续架构阶段确认。

## 9. 关键风险

1. **Gatekeeper / 未签名应用**：macOS 可能阻止未签名应用运行，需要测试并准备绕过方案或说明；
2. **自动保存失败**：磁盘满、路径不可写、文件被占用时，必须有清晰的错误提示且不丢失用户输入；
3. **跨平台一致性**：图片粘贴、文件路径、配置存储在 Windows 上的行为可能与 macOS 有差异，第二版需重新验证。

## 10. 愿景

成为受控办公环境下最轻量、最可靠的 Markdown 记录工具。未来可逐步扩展为：支持图片/附件、Confluence 一键同步、模板片段、以及跨 Windows 的通用知识工作者编辑器。
