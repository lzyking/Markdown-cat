## 遇到的挑战与教训

1. **Tauri 前端 Hash 与单独 `cargo check` 的依赖关联**
   - 在独立执行 `cargo check` 时，Tauri 框架会检查 `frontendDist` 的静态资源。若未跑 `npm run build` 生成前端文件，单独 cargo 校验会报资源 hash 不匹配。
   - **教训**：对于纯前端与 UI 逻辑变更，以 `npm run build` 类型校验与 Playwright E2E 回归测试为准。

2. **E2E 测试匹配精度的严谨性**
   - Story 2.2 审查中发现，延迟测试循环中使用 `.includes('line')` 可能会被前一次迭代残留的内容误判。
   - **教训**：E2E 测试中的断言与 `waitForFunction` 必须针对当次输入的唯一参数（如 `line ${i}`）进行精确匹配，消除时序漏洞。
