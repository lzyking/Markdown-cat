## 做得好的地方

1. **绝对的数据零损伤与保底安全 (Resilience)**
   - 无论磁盘满、目录不可写还是系统权限受限，编辑器的内存 `content` 始终零损毁、零截断。
   - 错误发生后自动防抖仍保持监听，用户调整路径或修正文本后后续防抖重试会自动恢复成功态。

2. **精确的 300ms 防抖控制与性能防护**
   - 防抖以 `content` 变化事件为触发单位，完美避开了 IME 组合输入时的碎片触发。
   - 重置（Reset）机制确保仅在连续键入完全停止 300ms 后发起 1 次写盘命令，杜绝高频磁盘 I/O 与并发写入冲突。

3. **WCAG AA 友好的防闪烁状态保留**
   - 自动保存成功后呈现 `已保存至 {filename}` 提示与绿色圆点。
   - 用户开启新一轮键入时，标题栏圆点隐藏（回到 unsaved），但状态栏持续保留上次的成功存盘提示，有效防止文案抖动闪烁。

4. **Tauri 2.x API Mock 体系深化**
   - 响应测试需求，在 `e2e/fixtures.ts` 中补全了 `w.__TAURI_INTERNALS__` 与 `save_document` 模拟，使得底层 async/await IPC 可以在无原生 Rust 环境下实现精准到毫秒的自动测试。

## 遇到的挑战与教训

1. **Tauri 2.x `@tauri-apps/api/core` 内部 API 依赖细节**
   - 在测试 Story 3.1 时，因为 API Mock 仅暴露了 `__TAURI_MOCK__`，调用 `@tauri-apps/api/core` 的 `invoke` 抛出了 `Cannot read properties of undefined (reading 'invoke')`。
   - **教训**：Frontend API Mock 必须同步更新支持 Tauri SDK 的 `__TAURI_INTERNALS__` 入口，确保开发框架升级时不产生阻断。

2. **异步 Promise 微任务与 Fake Timers 的结合**
   - 在 Playwright 测试脚本中使用 `fakeTimers.tick(300)` 时，仅推动了定时器触发，仍需刷新 ES6 微任务队列（`await Promise.resolve()`）以确保 `async invoke` 回调全流程执行。
   - **教训**：在假定时器驱动 async/await 代码测试时，必须显式刷新微任务队列，保证异步 DOM 渲染落地。
